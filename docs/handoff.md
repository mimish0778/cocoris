## 1. プロダクト概要

### 名称

| 用途 | 表記 |
|---|---|
| ユーザー向け表示 | **ココリス** |
| リポジトリ・フォルダ・パッケージ | `cocoris` |
| クラス名・型名（PascalCase必要箇所） | `Cocoris` |
| 定数 | `COCORIS` |

- `CocoRis` / `coco_ris` などの表記ゆれは**使わない**（grep が効かなくなる、大小無視FSとLinuxで事故る）
- 由来: 「ここ」＋「リスク」のダブルミーニング。加えて**リス（栗鼠）**＝木の実を埋めた場所を覚えている動物＝ユーザーの行動範囲を記憶するアプリ、というメタファー
- **マスコットは栗鼠で確定**
- 未対応タスク: 「ココリス」の既存サービス・商品名との衝突チェック、`cocoris` の npm/PyPI 空き確認、ドメイン確認

### コンセプト

> **ハザードマップを、あなたの生活時間に射影する**

危険な場所を教えるのではなく、**あなたにとって危険な時間と場所**を教える。

GPS履歴から生活圏を自動抽出し、「いつ・どこで・どんな危険にさらされやすいか」を返す。

### コピー案（未確定）

- ココリス — あなたのいつもの場所を、覚えている。
- リスは、木の実を埋めた場所を覚えている。ココリスは、あなたがよく行く場所を覚えている。
- いつもの場所が、いつも安全とは限らない。

## 2. 差別化ポイント（審査で最も重要）

| | 既存（東京都防災アプリ・防災cmap 等） | ココリス |
|---|---|---|
| 地点の指定 | ユーザーが手動登録（マイエリア） | **GPS履歴から自動抽出** |
| 時間の扱い | ほぼなし | **曜日×時刻×祝日で変化** |
| 混雑情報 | **発災後のみ** | **平常時から予測** |
| 出力 | 地点の危険度 | 生活圏の危険場所ランキング |

### 決定的な事実（プレゼンで使う）

東京都防災アプリの「帰宅困難者モード」（令和7年3月追加）は、混雑度が高まっている地域を確認して混雑を避けて一時滞在施設へ移動できる機能を持つが、**トップ画面に防サイくんが表示された時（＝発災時）のみ利用可能で、平常時は利用できない**。

→ **平常時に自分の生活圏の混雑・リスクを知る**という領域は空いている。ここがココリスの主張。

東京都の「キタコンDX」（帰宅困難者対策オペレーションシステム、2025年3月28日運用開始）もGPS等で混雑をリアルタイム可視化するが、これも**発災後**のシステム。

## 4. リスクモデル

災害リスク学の標準的な分解に揃える。

```
個人リスク = ハザード × 曝露(exposure) × 脆弱性(vulnerability)
              ↑            ↑                ↑
           場所固有    その時間にそこに    逃げにくさ
           時間非依存   いる確率          帰りにくさ
                       (GPSから推定)      (時間依存)
```

**注意**: 検討初期に「行動困難性」という第3項を使っていたが、これは脆弱性の一部でしかない（建物の耐震性能なども脆弱性）。**審査員への説明は標準の3項に揃えること。**

### 時間帯仮説の検証結果 → 正しい

ただし定義に注意:

- ❌ 「夜はこの場所の危険度が高くなる」
- ✅ 「夜にこの場所にいる**あなた**にとっての災害リスクが高くなる」

場所固有のハザード（建物の耐震性）は昼夜で変わらない。変わるのは**曝露**と**脆弱性**。

**行政データにも時間帯別評価は存在する**（＝思いつきではない根拠）:
東京消防庁の出火危険度は、**夏と冬 × 昼(11-13時台)と夕方(17-19時台)** で測定され、**冬の夕方が最も高い**ため以降は冬の夕方を中心に結果を表示している。

| 東京都デジタルツイン 3次元点群 | 東京都 | 建物高さの検証用 | 任意 |

#### 地域危険度（第9回）の詳細

- 都内市街化区域 **5,192町丁目**
- 4指標: 建物倒壊危険度 / 火災危険度 / 災害時活動困難係数 / 総合危険度
- **相対評価5段階**
- CSV・**SHP** で公開 → **ポリゴンと属性が最初からセット**。e-Stat小地域境界と名前で結合する必要がなく、事故を回避できる
- 建物倒壊危険度は「建物の種別（構造、建築年代、階数）や地盤特性によって、1haあたりの建物倒壊の棟数を算出した建物倒壊危険量」に基づく
  → **都は建物属性を持っているが、公開は町丁目集計値**
- 危険度の高い地域は「揺れが増幅されやすい沖積低地等の地盤で、古い木造や軽量鉄骨造の建物が密集している地域」
  → 「古い木造＋軟弱地盤」の掛け算は都の分析そのもの
- **ランクではなく「危険量」（棟/ha の連続値）を使うこと**。ランク5の中にも幅があり、スコアリングには連続値の方が階調が素直に出る
- 未確認: 公開CSV/SHPに**地盤分類カラムがあるか**。なければ重ねるハザードマップの「地形分類」で代替

#### PLATEAU の重要な注意点

- LOD1 は東京23区全域（627.57k㎡）をカバー、多摩地域も整備あり。商用利用含め無償
- 建物ポリゴン＋用途・階数・高さ・構造（`buildingStructureType`）・建築年（`yearOfConstruction`）
- **⚠️ 属性は「当該地方公共団体と協議の上決定」されるため、建築年が全建物に入っているとは限らない**
- **必ず実ファイル（CityGML）を落として充足率を実測すること**。「あるはず」で進めない
- 全区落とす必要はない（4.2GB）。渋谷区あたりの1メッシュで傾向が見える
- 充足率次第で企画の解像度が決まる:
  - 埋まっている → 建物単位のリスク推定
  - スカスカ → 町丁目単位に降格（企画は成立する）

#### 使えないデータ（誤解注意）

**警視庁「交通量統計表」は面的な混雑に使えない。**
都県境および都内主要交差点等 244か所を、**全て平日**に、年/隔年で観測した**点データ**。「平日/休日の比較」や「面的な混雑度」には使えない。

道路交通センサスも最新が令和3年度（公表 令和5年6月）で約5年おき、休日観測は地点が限定的。

→ **混雑は JARTIC のAPI が本命。**

#### エクスポート手順

**iPhone**
1. Googleマップアプリ → 右上のプロフィール写真 → 「タイムライン」
2. 右上の「…」（その他アイコン）
3. 「位置情報とプライバシーの設定」
4. 下にスクロール → 「タイムラインデータをエクスポート」
5. 保存先を選択（ファイルアプリ / Googleドライブ）

1. 「設定」アプリ → 「位置情報」 → 「位置情報サービス」 → 「タイムライン」
2. 「タイムラインをエクスポート」
※ Googleマップアプリ側（iPhoneと同手順）から辿れることもある。機種でメニュー名が異なるため「タイムライン」項目の中を下まで探す

**出力**: JSON形式。サイズは数十MB程度になることがある。ファイル名は `location-history.json` 等

#### タイムラインの決定的な利点

**生のGPS座標の羅列ではなく、Googleが既に「どこに、何時から何時まで滞在したか」に整形済み。**

→ 半径150m/20分といった**滞在判定を自前で実装しなくてよい**。訪問セグメントがそのまま滞在地点として使える。1週間しかない状況では非常に大きい。

#### 未確認事項

JSONの実際の構造。仕様変更で変わっているため、実物を見るまでパーサは書けない。データが取れたら以下を確認する:
- トップレベルのキー
- 訪問(visit)と移動(activity)の区別方法
- 緯度経度・開始終了時刻のキー名

## 6. アルゴリズム設計

### 6-1. 滞在判定

タイムラインが整形済みなので基本は不要だが、自前実装する場合の目安:

```
滞在の定義: 半径150m以内に20分以上
```

**除外すべきもの**
- 移動中の停止（信号待ち、渋滞、駅ホームでの待機）→ 前後が移動セグメントなら滞在としない
- 単発訪問（訪問回数1回、かつ直近1週間以内でない）

**絞らないと起きる問題**: ランキング上位が通過点（駅・交差点・車内）で埋まり、「生活圏」ではなく「移動経路」になってしまう。

### 6-2. 重要度ランキング

**単位は「場所」（決定済み）**

```
重要度 = 行動スコア × リスクスコア
          ↑            ↑
    頻度・滞在時間   ハザード・混雑
```

**⚠️ 掛け算の落とし穴**: リスクが低い場所は行動スコアが高くても沈む。安全な地域に住んでいる人は**自宅がランキングに出てこなくなる**。

→ **自宅は別枠で常時表示**とし、ランキングは「自宅以外」とする。（掛け算＋自宅別枠 で確定）

**行動スコアは累積時間だけで並べないこと。**
累積時間ソートだと自宅が常に1位で固定され、画面が動かなくなる。

```
生活圏スコア = f(訪問回数, 1回あたり平均滞在, 直近性)
```

2軸で考える:

| | 頻度が高い | 頻度が低い |
|---|---|---|
| **1回が長い** | 自宅・職場・大学 ★最重要 | 実家・旅行先 |
| **1回が短い** | スーパー・駅・ジム | ノイズ（除外） |

「毎週20分のスーパー」は累積時間では下位だが防災的に意味がある。「1回だけ3時間いた初訪問の店」は上位に来ても生活圏ではない。

### 6-3. 時間減衰【重要な修正あり】

**素朴な「過去30日窓」は使わない。**

問題: 31日目に突然ランキングから消えて唐突。「30日前の1回」と「昨日の1回」が同じ重みなのも直感に反する。

**指数減衰を使う:**

```
重み = 0.5 ^ (経過日数 / 半減期)
半減期 = 14日
```

| 経過日数 | 重み |
|---|---|
| 0日（今日） | 1.00 |
| 7日前 | 0.71 |
| 14日前 | 0.50 |
| 30日前 | 0.23 |
| 60日前 | 0.05 |

- 訪問1件ごとに重みを掛けて足すだけ。実装は簡単
- データ保持は90日程度で十分（それ以前は重み0.01未満）
- 「この前までよく行っていた場所が徐々に沈む」という意図した挙動になる
- **副次的利点**: 引っ越し・転職に自動追随（新居が2週間で旧居を追い抜く）。特別な処理不要

### 6-4. 期間と季節性の分離

行動パターンとハザードの時期を**分離する**:

- **行動パターン**: 直近30日（指数減衰）
- **リスク評価の時期**: ユーザーが切り替え（「冬の夕方」「夏の昼」など）

理由: 出火危険度が冬の夕方で最大である以上、夏のデータで冬のリスクを語ることになる。行動を変えるのではなく、**当てるハザードを変える**。

### 6-5. 出力の作法

**絶対確率は出さない。** 地域危険度は町丁目単位の相対評価なので、「倒壊確率37%」は根拠のない数字になる。

```
❌ この建物の倒壊確率は37%です
✅ あなたの生活圏の中で、この場所が相対的に最も危険です
   （理由：1975年築・木造・沖積低地・倒壊危険量ランク5）
```

## 8. UI設計

### タブ構成

```
[リスク地図]  [あなたの危険場所]  [設定]
```

**デフォルト起動はランキングタブ。** 地図を最初に見せると「よくある防災アプリ」に見え、差別化が第1画面に来ない。

### 時刻はグローバル状態

タブごとに別の時刻を持たない。**「いま何時を見ているか」をアプリ全体で1つ**持つ。

- 起動時＝現在時刻
- ランキングで「平日18時」を選ぶ → 地図タブも18時になっている
- 地図でスライダーを動かす → ランキングの順位も入れ替わる

**この連動自体が、時間軸を扱っていることの証明になる。デモで最も効く挙動。**

### タブ1: リスク地図

純粋なハザードマップにしないこと（既存アプリと同じになる）。

```
├ ハザードレイヤ（建物倒壊 / 火災 / 浸水 / 土砂 / 帰宅困難）
├ 時間スライダー（0-24時、平日/休日/祝日）
└ ★ あなたの生活圏ピン（オーバーレイ、ON/OFF可）
```

自分の生活圏ピンがハザードの濃い領域に重なっているのが見える、というのが本来の絵。

逆方向の導線: 地図で任意地点をタップ → 生活圏内なら「ここはあなたが週2回訪れています」と表示。

### タブ2: あなたの危険場所（ランキング）

**空状態**（履歴がない場合）:
```
まだ十分な履歴がありません

3日分の履歴が溜まると表示されます

        [ リスク地図を見る ]
```
※「あと数日」より「3日分」と具体的に書く方が離脱が減る。導線を地図タブに逃がして行き止まりを回避。

**項目タップ → 詳細ボトムシート**:
```
渋谷駅周辺                    重要度 ★★★★★
─────────────────────────
  あなたの行動
    訪問頻度      週2.5回      ★★★★☆
    平均滞在      45分         ★★★☆☆
  この場所のリスク
    建物倒壊      ランク3      ★★★☆☆
    出火(冬夕方)  ランク4      ★★★★☆
    帰宅困難                   ★★★★★
    浸水                       ★☆☆☆☆
─────────────────────────
  1975年以前の木造建物が密集し、地盤が
  軟弱なため、揺れが増幅されやすい地域です。
─────────────────────────
  [ 地図で見る ]   [ この場所を除外 ]
```

**★の設計ルール**
- ★の意味は1種類に統一
- 行動側の★＝「あなたの中での相対値」、リスク側の★＝「都内5,192町丁目の中での相対値」
- **出自が違うので見出しで区切る**。混ぜて縦に並べると★4の意味が2種類混在して読めない
- 地域危険度のランクをそのまま★に流用しない。危険量（連続値）から引き直す

**「なぜ危険か」の1文要約**: 建物属性と地盤分類の組み合わせをいくつかのパターンに分類し、定型文を出す。

**「この場所を除外」は必須**: 自動抽出は誤検出するので、訂正できないと信頼を失う。

### ランキング → 地図 の遷移

**座標だけ渡すと失敗する。3つの状態をまとめて持っていく。**

```
「渋谷駅周辺 / 平日18-19時 / 帰宅困難 非常に高」
  ① 座標          → 渋谷駅にセンタリング
  ② 時間帯        → スライダーが18時に合っている
  ③ 災害種別レイヤ → 帰宅困難レイヤがON
```

座標だけだと、地図に飛んだ瞬間に「なぜ危険と言われたのか」が消える。
**ランキングは主張、地図はその根拠**という関係にしないと2つのタブが別アプリになる。

戻るときは「ランキングに戻る」を明示的に出す（ブラウザバック任せにしない）。

### タブ3: 設定

機能置き場ではなく**プライバシーへの回答**として設計。審査で必ず突かれる。

- 位置情報の利用 ON/OFF（OFFでも手動登録モードで使える）
- **履歴の全削除ボタン**（ワンタップ、確認1回）
- 保持期間（30日 / 90日 / 無期限）
- 手動での場所登録・編集（自動抽出の誤りを直せる）
- 表示する災害種別の取捨

### サブセクション案

滞在は短いが重要な乗換駅を落とさないため:
```
[ 生活圏ランキング ]  ← 滞在ベース、メイン
[ よく通る場所 ]      ← 通過ベース、駅・幹線道路
```
混ぜると「なぜ渋谷駅が2位なのか」の説明が難しくなるので分ける。

### 数字（混同注意）

| 想定 | 帰宅困難者数 |
|---|---|
| 東京都 2022年想定 | 東京都 **約453万人** |
| 国 2013年想定 | 東京都 約380〜490万人 / 1都4県 約640〜800万人 |
| **国 2025年想定**（2025/12/19公表） | 東京都 **約480万人** / 1都4県 **約840万人** |

- 国の被害想定は **2025年12月19日**に約12年ぶりに改定。首都直下地震モデル・被害想定手法検討会「地震モデル報告書」および中央防災会議WG「首都直下地震の被害想定と対策について（報告書）」
- 2025年想定では手法見直しにより帰宅困難者は**増加**。「行き場あり/なし」の内訳も公表（1都4県で行き場なし約160万人）。観光・出張客等が約65〜88万人滞留
- 2025年想定は「帰宅者集中により道路の混乱が悪化し緊急車両の通行も困難になる」と明記、鉄道の長期運休による出勤困難の長期化も過酷事象として記載
  → **混雑×時間帯の着眼点を裏付ける最新の一次資料**

### 補足

- 重ねるハザードマップ/ハザードマップポータルの運営は**国土交通省**（掲載情報の担当が国土地理院）
- 「2025年の都知事杯ハッカソンで地域危険度×人口×避難所の作品があった」は**裏取りできていない**。既存事例として言及するなら作品名レベルで要確認
