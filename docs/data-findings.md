## 確定した事実

### 地域危険度 SHP
- **CRS は EPSG:2451**（JGD2000 平面直角座標系第9系）。緯度経度ではない。**要変換**
- 5,192ポリゴン、総頂点 811,335
- 属性: `ID / 区市町村名 / 町丁目名 / 建物_危 / 建物_順 / 建物_ラ / 火災_危 / 火災_順 / 火災_ラ / 災害_係 / 総合_危 / 総合_順 / 総合_ラ`
- **危険量は連続値で入っている**（例 2.01474011 棟/ha）。handoff の方針どおりランクではなくこちらを使える
- **SHPに地盤分類は無い**
- 131ポリゴンが不正ジオメトリ（`buffer(0)` で修復済み）

### 地域危険度 CSV
- **地盤分類カラムは存在する** → 重ねるハザードマップでの代替は不要。handoff §12 の TODO は解決
- 12分類と件数: 台地1=2447 / 沖積低地4=518 / 沖積低地2=378 / 沖積低地5=309 / 台地2=297 / 丘陵=295 / 沖積低地3=289 / 谷底低地2=251 / 沖積低地1=170 / 谷底低地1=124 / 谷底低地3=64 / 山地=50
- SHPとの結合は `区市町村名+町丁目名` で **100%**（同一出典なので当然）

### 出火危険度 XLSX
- **第10回**。ヘッダ3行、データは4行目から5,264件
- 列: `[0]町丁目名 [1-5]冬夕 要因別(火気器具/電気関係/工業炉/危険物施設/その他) [6]冬夕木造 [7]冬夕非木造 [8]冬夕総合 [9]夏昼総合`
- **`冬夕` と `夏昼` の両方が1ファイルに入っている** → handoff §4 の時間帯仮説を、単一の公式データセット内の2列で直接示せる。プレゼン素材として強い
  - 例: 荒川区町屋1丁目 = 冬夕ランク4 / 夏昼ランク2、渋谷区渋谷2丁目 = 冬夕3 / 夏昼1

### 名寄せ（handoff §12「要注意」への回答）
町丁目名の結合率は **99.58%（5,170 / 5,192）**。正規化ルールは `scripts/norm.py`。

素の突合わせは 98.57%。潰した差分は全て systematic だった:

| 差分 | 件数 | 例 |
|---|---|---|
| 丁目が漢数字 / 全角算用数字 | 全件 | `飯田橋一丁目` ⇔ `飯田橋１丁目` |
| 全角スペースの右詰めパディング（消防庁側） | 全件 | `千代田区一番町　　　　` |
| 郡名の有無 | 23 | `西多摩郡瑞穂町○○` ⇔ `瑞穂町○○` |
| ヶ / ケ の揺れ | 11 | `千駄ヶ谷` ⇔ `千駄ケ谷` |
| 千代田区の「神田」接頭辞 | 5 | `神田三崎町` ⇔ `三崎町` |
| 異体字 | 1 | `渕上` ⇔ `淵上` |

**残る22件は表記ゆれではなく実体差**（第9回=令和4年 と 第10回 の時点差による区画整理）。正規化では原理的に解けないので、UIでは「出火危険度データなし」を返す:
町田市南町田1-5/小川5-7/鶴間4-8、昭島市もくせいの杜1-3、国立市泉5・谷保6-7、江戸川区東瑞江3・瑞江4、新宿区四谷坂町。

出火危険度側に余る94件は奥多摩町・あきる野市の山間部と中央防波堤で、**市街化区域外＝地域危険度の対象外**。正常。

## 成果物: `public/data/chochome.json`

`scripts/build_dataset.py` が3ファイルを1つに統合。

- 5,192フィーチャ、WGS84、**tolerance 5m で簡略化**（頂点 811,335 → 111,425 = 13.7%）
- 生 4.65 MB / **gzip後 0.84 MB**
- properties: `id, city, town, ground, collapseQty, collapseOrder, collapseRank, fireQty, fireOrder, fireRank, difficulty, difficultyOrder, totalQty, totalOrder, totalRank, shukkaWinterEve, shukkaSummerNoon, shukkaWoodWinterEve, shukkaNonWoodWinterEve`
- **順位（Order）が★の根拠**。1 = 都内で最も危険。`difficultyOrder` だけは元データに順位が
  無いので `build_dataset.py` で災害時活動困難係数の降順から作っている

### プライバシー設計への影響（handoff §9 の更新）

gzip 0.84MB ならクライアントに全部同梱できる。**ハザードAPIをサーバーに置く必要が無い。**

```
旧案: ブラウザで滞在抽出 → 町丁目コードだけサーバーに送信 → ハザードスコアを受信
新案: ブラウザで滞在抽出 → 同梱データでpoint-in-polygon → 何も送信しない
```

「位置情報は端末から出ません」ではなく **「サーバーへの通信そのものが無い」** と言い切れる。
Cloudflare は静的配信のみ。実装量も減る。
