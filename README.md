# ココリス（cocoris）

> あなたのいつもの場所を、覚えている。

よく行く場所だけを 1 枚の地図にまとめて、災害時に危ない順に並べ、逃げるならどこへ行けばいいかまで教えてくれる Web アプリです。

ハザードマップは災害の種類も地図の枚数も多すぎて、自分がどこを見ればいいのか分かりにくいものです。ココリスは位置履歴から「あなたが実際にいる場所」を拾い、そこに当てはまる情報だけに絞って見せます。時刻や災害の種類を選ぶ操作はありません。

主な対象は、乳幼児を育てている親です。都知事杯オープンデータ・ハッカソン 2026 の提出作品です。

## できること

画面は 3 つのタブに分かれています。

- **ランキング** — よく行く場所を危険度の高い順に並べます。各行にその場所の避難先が書いてあり、タップすると避難場所までの地図と「なぜ危険か」の説明が開きます。
- **備蓄リスト** — 子どもの生まれ月を入れると、月齢に合った備蓄のチェックリストを作ります。粉ミルクか離乳食か、おむつのサイズはいくつか、といった必要なものは月齢で変わるためです。
- **アンケート** — 避難所の設備（授乳スペース、アレルギー対応、ベッドの有無など）を、その場にいる人に答えてもらう画面です（[未完成](#未完成の部分)）。

場所の入れ方は 3 通りあります。

1. **サンプルデータで試す** — 荒川区に住む乳幼児の親を想定したデータで、すぐに動きを見られます
2. **自分の履歴をインポート** — Google マップのタイムラインをスマホアプリからエクスポートした JSON（東京都内の滞在のみ）
3. **手動で登録** — よく行く場所と時間帯を自分で入れる

## 動かし方

```sh
npm install
npm run dev     # http://localhost:5173
```

```sh
npm test        # vitest（src/core/ のロジック、58 件）
```

ハザードデータ（`public/data/`）はリポジトリに入っているので、そのまま動きます。

### API キー（なくても動きます）

プロジェクト直下に `.env.local` を作ると、追加の機能が有効になります。変数名の `VITE_` は必須です（Vite はこれが付いた変数だけをブラウザ側に渡します）。変更したら開発サーバーを再起動してください。

```sh
VITE_ORS_TOKEN=...     # 避難経路を実際の道に沿って描く
VITE_GEMINI_TOKEN=...  # 場所ごとの AI アドバイス欄を出す
```

- **`VITE_ORS_TOKEN`** — [OpenRouteService](https://openrouteservice.org/dev/#/signup)（HeiGIT が運営する非営利サービス）のトークン。メールアドレスだけで登録でき、無料枠は 1 日 2,500 件です。ないときは避難場所まで直線の点線を引き、「実際の道のりではありません」と表示します。
- **`VITE_GEMINI_TOKEN`** — [Google AI Studio](https://aistudio.google.com) で発行する Gemini の鍵。ないときはアドバイス欄が出ないだけです。無料枠は 15 RPM なので、続けてタップすると 429 が返ることがあります。

経路探索に Mapbox ではなく ORS を選んだのは、Mapbox はトークンの発行にクレジットカードの登録が必要だからです。

#### 鍵はビルド結果から読めてしまいます

静的サイトなので、埋め込んだ鍵は誰でも読めます。ORS には URL 制限の機能もありません。ただ、カードを登録していないので、悪用されても 1 日の上限に達して経路が出なくなる（自動で直線表示に切り替わる）だけで、お金の被害は出ません。

完全に隠すにはプロキシ（Cloudflare Pages Functions など）が必要ですが、そうするとバックエンドを持つことになるので見送っています。差し替えやすいよう、`VITE_ORS_TOKEN` を読むのは `src/ui/EvacuationMap.tsx` と `src/ui/MapHome.tsx` の 2 ファイルだけにしてあります。

## 位置情報の扱い

位置履歴は端末から出ません。JSON はブラウザが File API で直接読み、滞在場所の抽出、町丁目の判定、避難場所の割り当てまで、すべてブラウザの中で終わります。ハザードデータ（都内 5,192 町丁目）と避難場所の指定をアプリに同梱しているので、座標をサーバーに送る必要がなく、そもそもバックエンドがありません。

ただし、外部に伝わる情報が 3 つあります。

- 背景地図（地理院タイル）の取得で、表示している地図の範囲が伝わります
- 経路探索を使うと、その場所と避難場所の座標が OpenRouteService に渡ります
- アンケートタブでは、いまいる避難所を特定するために `navigator.geolocation` で現在地を取得します（判定は端末内のみで、外には送りません）

上の 2 つは起動画面と設定画面にも書いてあります。「位置情報は一切外に出ない」とは言えないので、説明するときは注意してください。

## 使っているデータ

- 地震に関する地域危険度測定調査（第 9 回）／東京都都市整備局 — 建物倒壊・火災・災害時活動困難度
- 町丁目別出火危険度（第 10 回）／東京消防庁 — 冬の夕方と夏の昼の出火危険度
- 震災時火災における避難場所及び避難道路等の指定（第 9 次）／東京都都市整備局

避難先は「最寄り」を計算しているのではなく、東京都が町丁目ごとに割り当てている公式の避難場所を出しています。

出典とライセンスは [docs/opendata.md](docs/opendata.md)、データを実際に見て分かったことは [docs/data-findings.md](docs/data-findings.md) にまとめています。

元データからデータセットを作り直すときは、`data/raw/` を用意してから次を実行します。

```sh
python scripts/build_dataset.py     # 町丁目とハザード
python scripts/build_evacuation.py  # 避難場所の割り当て
```

## ディレクトリ構成

```
src/core/    ロジック（DOM・React・localStorage に依存しない純粋な TypeScript）
src/ui/      React の画面
src/data/    サンプルデータ（乳幼児の親のペルソナ）
scripts/     元データの取得・検証・変換（Python）
public/data/ 同梱するハザード・避難場所データ
docs/        引き継ぎ資料、調査結果、提出資料
```

将来 React Native に移植するときに `src/ui/` だけを差し替えればいいように、`src/core/` には `document` や `window`、React を持ち込まないようにしています。

## デプロイ

静的サイトなので、ビルドした `dist/` を置くだけです。Cloudflare Pages の無料プランで足ります。

```sh
npm run deploy   # = npm run build && wrangler pages deploy dist --project-name cocoris
```

初回は Cloudflare へのログインが必要です。`dist/` を直接アップロードする方式なので、位置履歴を含みうるリポジトリを外部に連携する必要はありません。

配信時の注意:

- ハザードデータは `.geojson` ではなく `.json` にしています。`application/geo+json` は CDN の圧縮対象外のことがあり、4.65MB が無圧縮で配信されてしまうためです（`.json` なら gzip で 0.84MB）。転送量は全体でおよそ 1.3MB です。
- データを `/data/chochome.json` という絶対パスで読んでいるので、サブパスに置く場合は `vite.config.ts` の `base` を設定してください。

## 未完成の部分

アンケートの回答は、その端末の localStorage に保存されるだけで、ほかの利用者とは共有されません。いまは画面の形を示しただけのものです。

本当にやりたかったのは、集まった設備情報を、これから避難する人の行き先選びや物資の配分に役立てることでした。それには回答を集めるバックエンドと、回答がまだ少ない時期をどう補うかの設計が必要で、どちらも手つかずのまま提出しています。この作品のいちばん弱いところです。

実装状況や設計上の判断、残っている課題は [docs/status.md](docs/status.md) にまとめています。
