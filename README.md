# ココリス（cocoris）

> あなたのいつもの場所を、覚えている。

ハザードマップは災害の種類も地図の枚数も多すぎて、自分がどこを見ればいいのか分かりません。
ココリスは、あなたがよく行く場所だけを1枚にまとめて、危ない順に並べ、逃げるならどこへ行くのかまで表示します。
時刻や災害の種類を選ぶ操作はありません。

対象は乳幼児を育てている親です。防災の情報はすでに十分あるのに、自分に当てはまる部分が分からない。
その状態を、その人に必要な分だけに絞ることで解消しようとしています。

都知事杯オープンデータ・ハッカソン 2026 の提出作品です。

## 何ができるか

画面は3つのタブに分かれています。

- **ランキング**（`src/ui/RankingTab.tsx`）
  よく行く場所を位置履歴から自動で抽出して、災害リスクの高い順に並べます。
  一行ごとに、その場所の避難先まで書いてあります。
- **備蓄リスト**（`src/ui/StocklistTab.tsx`）
  子どもの生まれ月を登録するだけで、月齢に合った備蓄のチェックリストを作ります。
  粉ミルクか離乳食か、おむつのサイズはいくつか、といった必要なものは月齢で変わるためです。
- **アンケート**（`src/ui/SurveyTab.tsx`）
  避難所の設備（授乳スペース、アレルギー対応、ベッドの有無）を、そこにいる人に答えてもらう画面です。

ランキングから場所を選ぶと詳細シートが開き、上部に避難場所までの地図（`EvacuationMap.tsx`）が出ます。
Gemini のアドバイス欄（`GeminiComment.tsx`）も付きますが、これは鍵がなければ表示されません。

### アンケートは未完成です

回答は `src/ui/storage.ts` を通してその端末の localStorage に保存されるだけで、
サーバーがないため他の利用者には共有されません。今のところ動く形を示しただけのものです。

本来やりたかったのは「集めた設備情報を、これから避難する人の行き先選びや物資の分配に役立てる」ことでした。
それには回答を集約するバックエンドと、回答がまだ集まっていない時期をどう埋めるかの設計が要ります。
どちらも手つかずのまま提出しました。この作品の一番弱いところです。

## 避難経路を道なりで描くには

経路を実際の道に沿って描くには OpenRouteService（ORS。HeiGIT が運営する非営利サービス）の鍵が要ります。
鍵がなくてもアプリは動きます。その場合は直線を点線で描き、「実際の道のりではありません」と画面に出します。

Mapbox ではなく ORS を使っているのは、Mapbox はトークンの発行にクレジットカードの登録が必須だからです。
ORS はメールアドレスだけで無料枠（1日2,500件）が使えます。カードを登録していないので、
万一鍵が漏れてもお金の被害は出ません。

1. https://openrouteservice.org/dev/#/signup でサインアップする（カード不要）
2. メール認証のあと https://openrouteservice.org/dev/#/home でトークンを発行する（プランは Standard）
3. プロジェクト直下に `.env.local` を作る

```bash
VITE_ORS_TOKEN=ここに鍵
VITE_GEMINI_TOKEN=ここにGemini鍵
```

4. 開発サーバーを再起動する（環境変数は起動時にしか読まれません）

`VITE_GEMINI_TOKEN` は Google AI Studio（aistudio.google.com）で発行します。
こちらも無くて構いません（AIアドバイス欄が消えるだけです）。無料枠が 15 RPM なので、
連続でタップすると 429 が返ることがあります。

`VITE_` という接頭辞は必須です。これが付いた変数だけが Vite からブラウザ側に渡ります。

### 鍵は隠せません

静的サイトなので、ビルド結果に埋め込んだ文字列は誰でも読めます。難読化しても意味がありません。
ORS の鍵には Mapbox のような URL 制限の機能がないため、鍵は露出したままになります。

ただしカードを登録していないので、悪用されても1日2,500件の上限に達して経路が出なくなるだけです。
そうなったときは自動で直線表示に切り替わります。お金の被害は出ません。

完全に隠すにはプロキシ（Cloudflare Pages Functions など）が必要ですが、
それを置くとバックエンドができてしまい、「サーバーはありません」と言えなくなります。
差し替えるときのために、`VITE_ORS_TOKEN` を読んでいるのは
`src/ui/EvacuationMap.tsx` と `src/ui/MapHome.tsx` の2ファイルだけにしてあります。

## 位置情報の扱い

位置履歴は端末から出ません。ブラウザが File API で直接読み、滞在した場所の抽出も町丁目の判定も
ブラウザの中だけで終わります。ハザードデータ（都内5,192町丁目、gzip で約0.84MB）をアプリに同梱しているので、
座標も町丁目コードもサーバーへ送る必要がありません。そもそもバックエンドがありません。

ただし、外部に伝わるものが3つあります。

- 背景地図（地理院タイル）には、表示している地図の範囲が伝わります
- 経路探索を使っている間は、その場所と避難場所の座標が openrouteservice に渡ります
- アンケートタブは `navigator.geolocation` で現在地を取得します（今いる避難所を特定するため）。
  取得した座標は端末の中で避難場所の判定に使うだけで、外へは送りません

上の2つは起動画面と設定画面に書いてあります。
「位置情報は端末から出ません」と無条件に言わないでください。

## 構成

```
src/core/    DOM に依存しない純粋な TypeScript。ロジックは全部ここ（localStorage も使わない）
src/ui/      React。ネイティブへ移植するときはここだけ差し替える
src/data/    サンプルデータ（乳幼児の親のペルソナ）
scripts/     元データの取得・検証・変換（Python）
public/data/ 同梱するハザードデータ
docs/        引き継ぎ・調査結果・提出用の資料
```

`src/core/` には `document` や `window` や React を持ち込まないでください。
将来 React Native へ移植するとき、そのまま持っていける状態を保つためです。

## デプロイ

静的サイトなので、`npm run build` の出力（`dist/`）を置くだけです。
バックエンドがなく Cloudflare の有料機能も使っていないため、無料プランで足ります
（5ファイル・合計約6.3MB、最大は `public/data/chochome.json` の4.65MB）。
ハッカソンの特典が切れても運用を続けられます。

```bash
npm run deploy   # build してから wrangler pages deploy dist --project-name cocoris
```

分けて実行するなら以下です。

```bash
npm run build
npx wrangler pages deploy dist --project-name cocoris
```

初回は Cloudflare アカウントでのログインが要ります。
git リポジトリは不要で、`dist/` を直接アップロードします。
そのため、位置履歴を含みうるリポジトリを外部に置かずに済みます。

### 配信で気をつけること

- ハザードデータの拡張子は `.geojson` ではなく `.json` にしてあります。
  `application/geo+json` は CDN の圧縮対象に入っていないことがあり、4.65MB が無圧縮で配信される恐れがあるためです。
  `.json` なら `application/json` として確実に圧縮されます（4.65MB → gzip 0.84MB）
- 実際の転送量は合計およそ 1.3MB です（町丁目0.84 + 避難0.08 + JS 0.36 + CSS）
- サブパスに置くと `/data/chochome.json` という絶対パスが壊れます。
  ドメイン直下に置くか、`vite.config.ts` の `base` を設定してください
